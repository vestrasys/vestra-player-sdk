# Translate a plugin

Vestra Player (0.4.3 or later) shows its interface in English, Simplified Chinese (`zh-Hans`), Japanese (`ja`), Korean (`ko`), German (`de`), French (`fr`) or Spanish (`es`). The user picks one in **Settings ▸ Language** (or follows the system); the choice takes effect at the next start, and the language stays the same for the whole run. A plugin joins in by shipping one gettext file per language. It writes **no translation code**: the player translates.

The [Counter example](../examples/i18n.md) is a complete translated plugin. Moving an existing plugin over is in [Migrate a plugin to English source text](i18n-migration.md).

## The rule: English source text in three places

Every text a user can see is written in English, in one of three places, and the player looks it up in the plugin's catalog for the interface language. Untranslated text shows in English.

1. **Declarations.** What the plugin declares, the player shows translated:

   ```ts nocheck
   plugin.commands.add({
     id: "counter",
     path: ["Tools", "Counter…"], // English: menus merge by these words
     run: () => window.show(),
   });
   ```

   Command titles and paths, settings page titles (`settings.page`), panel and tab titles (`panels.mount`), command `reason`s, and the manifest's `name`, `punchline`, `description` and `tags`. Menus of different plugins merge by the English words, so plugins that share a submenu must write it the same way; the player's own menus are `Open`, `Playback`, `Subtitles`, `Video`, `Audio`, `Screen`, `Settings` (or `@video` and the other ids) and show in the player's words.

2. **Slint.** A window's texts belong in its `.slint` file, wrapped in `@tr`:

   ```slint
   title: @tr("Counter");
   Text { text: @tr("{n} click" | "{n} clicks" % root.count); }
   Button { text: @tr("Add {}", root.step); }
   ```

   TypeScript passes data (`count`, `step`), never finished sentences. `@tr` takes `{}`, `{0}`, `{1}` arguments and a plural form (`"one" | "other" % n`, where `{n}` is the number). The player has two plural forms: one for `n == 1`, the other for every other number. A context (`@tr("Menu" => "Open")`) tells two meanings of one English word apart.

3. **Sentences the plugin hands the player**: `osd.show`, `OsdPanel.set` and `dialogs.confirm` take a template and its arguments:

   ```ts nocheck
   await plugin.osd.show("Speed {}×", [rate]);
   await plugin.dialogs.confirm({
     message: "Delete {} bookmarks?",
     confirm: "Delete",
     args: [count],
   });
   ```

   Never build the sentence in TypeScript (`` `Speed ${rate}×` ``, `"Speed " + rate`): a translator can only translate a whole template, and word order differs between languages. Named arguments work too: `osd.show("{name} is ready", { name })`.

`plugin.i18n.locale` tells which language this run uses, for what is not text (a date: `date.toLocaleDateString(plugin.i18n.locale)`). There is no `t()` function and no event when the language changes: it never changes while the player runs.

## Files

```text
locales/
  messages.pot     every text to translate (written by vestra-plugin i18n extract)
  zh-Hans.po       Simplified Chinese
  de.po            German …
```

One `<lang>.po` per language you provide, named by its locale (`zh-Hans`, `ja`, `ko`, `de`, `fr`, `es`; English is the source and has none). They are ordinary gettext files: any `.po` editor (Poedit, Lokalize, Weblate, a text editor) works. `vestra-plugin build` compiles them into `dist/locales/<lang>.json`, which the player reads; during development (`--plugin <dir>`) the player reads the `.po` files directly.

## Commands

```sh
vestra-plugin i18n extract                # write locales/messages.pot, update every locales/<lang>.po
vestra-plugin i18n extract --locale de    # start a new language
vestra-plugin i18n check                  # coverage and problems (warnings only)
```

`extract` finds every `@tr` in the `.slint` files, the texts given to the calls above (literals, both branches of a `?:`, and `as const` tables, through the TypeScript type checker), and the manifest's display fields. It keeps existing translations, adds new texts untranslated, and moves texts that disappeared to the end of each `.po` as obsolete (`#~`), so a text that comes back keeps its translation.

`check` reports per language how much is translated, translations that lost or changed a placeholder (keep every `{…}` exactly as in the English; reorder with `{0}`, `{1}` only where the English has them), plural forms missing, a stale `messages.pot`, and text that cannot be translated: a sentence composed in TypeScript, a value that is not a literal, Chinese or other non-English source text, and Slint text without `@tr`. `vestra-plugin check` prints the same warnings when the plugin has a `locales/` folder; none of them fails a build.

A note for translators goes in a comment that starts with `TRANSLATORS:` right before the text (in TypeScript on the property or the call, in Slint on the line above the `@tr`); `extract` copies it into the files.

## Tests

`startPlugin(activate, { directory, locale: "zh-Hans" })` loads `locales/zh-Hans.po` and makes the test host show what a user of that language sees:

```ts nocheck
const { host, plugin, stop } = await startPlugin(activate, { directory, locale: "zh-Hans" });
assert.equal(plugin.i18n.locale, "zh-Hans");
assert.deepEqual(host.command("counter").display.path, ["工具", "计数器…"]);
assert.deepEqual(host.osd, ["计数：1"]); // osd.show("Count: {}", [1])
```

`command.display` is the menu as shown, `host.osd` and `host.confirmTexts` the shown messages, `host.translate(text, args)` any text. The declared English stays in `command.declaration` and `host.sent(...)`. Without `locale` the test host plays English, except that the player's own messages stay in the Chinese older SDKs used.

## Limits

- The language changes only at the next start of the player.
- Plurals have two forms (1 and everything else). For a language with more forms (Russian, Arabic, Polish) the player does not ship a translation.
- Numbers in templates print as JavaScript writes them (`1.5`), not in the language's own format.
- A text the player cannot find in the catalog shows in English; so does a plugin's text on a player before 0.4.3, which also shows templates without filling them in. Set `"minPlayerVersion": "0.4.3"` in the manifest of a plugin that relies on templates.
