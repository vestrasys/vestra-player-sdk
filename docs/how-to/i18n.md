# Translate a plugin

Vestra Player (0.4.3 or later) shows its interface in one of seven [languages](#languages). The user picks one in **Settings ▸ Language** (or follows the system); the choice takes effect at the next start, and the language stays the same for the whole run. A plugin joins in by shipping one gettext file per language. It writes **no translation code**: the player translates.

The [Counter example](../examples/i18n.md) is a complete translated plugin. Moving an existing plugin over is in [Migrate a plugin to English source text](../upgrading/i18n-migration.md).

## The rule: English source text in three places

Every text a user can see is written in English, in one of three places, and the player looks it up in the plugin's catalog for the interface language. Untranslated text shows in English.

1. **Declarations.** What the plugin declares, the player shows translated:

   ```ts nocheck
   plugin.commands.add({
     id: "counter",
     path: ["Tools", "Counter…"], // English: menus merge by these words
     run: () => window.show(),
   });
   ```

   Command titles and paths, settings page titles (`settings.page`), panel and tab titles (`panels.mount`), command `reason`s, and the manifest's `name`, `punchline`, `description` and `tags`. Menus of different plugins merge by the English words, so plugins that share a submenu must write it the same way; the player's own menus are `Open`, `Playback`, `Subtitles`, `Video`, `Audio`, `Screen`, `Settings` (or `@video` and the other ids) and show in the player's words.

2. **Slint.** A window's texts belong in its `.slint` file, wrapped in `@tr`:

   ```slint
   title: @tr("Counter");
   Text { text: @tr("{n} click" | "{n} clicks" % root.count); }
   Button { text: @tr("Add {}", root.step); }
   ```

   TypeScript passes data (`count`, `step`), never finished sentences. `@tr` takes `{}`, `{0}`, `{1}` arguments and a plural form (`"one" | "other" % n`, where `{n}` is the number). The player has two plural forms: one for `n == 1`, the other for every other number. A context (`@tr("Menu" => "Open")`) tells two meanings of one English word apart.

3. **Sentences the plugin hands the player**: `osd.show`, `OsdPanel.set` and `dialogs.confirm` take a template and its arguments:

   ```ts nocheck
   await plugin.osd.show("Speed {}×", [rate]);
   await plugin.dialogs.confirm({
     message: "Delete {} bookmarks?",
     confirm: "Delete",
     args: [count],
   });
   ```

   Never build the sentence in TypeScript (`` `Speed ${rate}×` ``, `"Speed " + rate`): a translator can only translate a whole template, and word order differs between languages. Named arguments work too: `osd.show("{name} is ready", { name })`.

`plugin.i18n.locale` tells which language this run uses, for what is not text (a date: `date.toLocaleDateString(plugin.i18n.locale)`). There is no `t()` function and no event when the language changes: it never changes while the player runs.

## Text that mixes words and data

Some text is neither a fixed declaration nor a window Slint can build: a menu item "Track 2 (opus)", a ComboBox model whose first item is "No Audio" and the rest track names, an OSD message whose reason is itself a sentence, a list of file names. For these, make a **text value** with `plugin.i18n.text(source, args)` (SDK 1.5.11, player 0.4.3) and pass it where a string would go. It is plain data, not a translation: the player translates `source` with the plugin's catalog and fills in the arguments when it shows it.

```ts nocheck
const { text, list } = plugin.i18n;

// A menu item with data (the menu merges by the English "Track 2 (opus)").
plugin.commands.add({
  id: `track-${n}`,
  path: ["@audio", "Audio Track", text("Track {} ({})", [n, codec])],
  run,
});

// A [string] model: fixed words and data in one list.
picker.set({ labels: [text("No Audio"), ...tracks.map((t) => text("Track {} · {}", [t.id, t.title]))] });

// An argument that is a sentence of its own.
await plugin.osd.show("Download failed: {}", [text("Connection timed out")]);

// Items joined the language's way: "a.glsl, b.glsl", "a.glsl、b.glsl".
await plugin.osd.show("Removed missing shaders: {}", [list(missing)]);

// A message of several parts, each translated: "Added: 3, duplicates skipped: 2".
await plugin.osd.show(list([text("Added: {}", [added]), text("duplicates skipped: {}", [skipped])], "clauses"));
```

Arguments are data (strings and numbers, shown as they are) unless they are text values themselves, which are translated too, to any depth (8 levels). `list(items, style)` joins with the interface language's separator: `"list"` (`, ` / `、`), `"clauses"` (`, ` / `，`), `"semicolons"`, `"sentences"` (`. ` / `。`) or `"lines"`.

A text value is accepted wherever the player shows a plugin's text:

| Where | Notes |
| --- | --- |
| `commands.add` `title`, `path` segments, `reason`; `Command.set({ reason })` | not a `list`; the menu merges by the English rendering |
| `osd.show(value)`, `OsdPanel.set(value)`, and as their `args` | a text value as the message carries its own args |
| `dialogs.confirm` `message`, `detail`, `confirm`, `cancel`, `checkbox` | `args` fills only the string ones |
| file dialog `title`; `saveFile` `fileName` | a string `fileName` is data; `text("Playlist.m3u8")` is translated |
| window, panel and settings page properties, where Slint has `string` | at any depth: `[string]` models, struct fields |
| `TimelineLayer.set` mark titles, `subtitles.load({ title })` | a plain string stays data |
| a resolver's failure: `throw plugin.i18n.error("The ROM file was not found.")` | shown translated as the open's failure and `player.state.error` |

`extract` collects the `source` of every `text(…)` and `error(…)` call (literals, `?:` branches, `as const` tables), whether called as `plugin.i18n.text` or destructured. Write the source as a literal, never `` text(`Track ${n}`) ``. A source made only of placeholders and punctuation (`"{} ({})"`, `"{0}: {1}"`) is collected like any other: languages differ in punctuation too (Chinese writes `"{}（{}）"`, `"{0}：{1}"`), and a translator who keeps it as it is simply copies it.

**Text that leaves the player.** What the plugin copies to the clipboard or writes to a file is not shown by the player. For that only, `plugin.i18n.resolve(value)` returns the translated string (with the same catalog the player uses): `clipboard.writeText(resolve(list(lines, "lines")))`. Never use it for the interface: a string resolved in TypeScript and then shown would hide the sentence from `check`, and the interface takes text values directly.

**OSD panel lines that must fit.** `OsdPanel.set(value, args, { maxColumns })` cuts each line after translation (a Chinese, Japanese or Korean character is two columns), so the plugin does not measure translated text.

## Files

```text
locales/
  messages.pot     every text to translate (written by vestra-plugin i18n extract)
  zh-Hans.po       Simplified Chinese
  de.po            German …
```

One `<lang>.po` per language you provide, named by its locale (the codes in [Languages](#languages); English is the source and has none). They are ordinary gettext files: any `.po` editor (Poedit, Lokalize, Weblate, a text editor) works. `vestra-plugin build` compiles them into `dist/locales/<lang>.json`, which the player reads; during development (`--plugin <dir>`) the player reads the `.po` files directly.

## Commands

```sh
vestra-plugin i18n extract                # write locales/messages.pot, update every locales/<lang>.po
vestra-plugin i18n extract --locale de    # start a new language
vestra-plugin i18n check                  # coverage and problems; fails on stale catalogs
```

`extract` finds every `@tr` in the `.slint` files, the texts given to the calls above (literals, both branches of a `?:`, and `as const` tables, through the TypeScript type checker), and the manifest's display fields. It keeps existing translations, adds new texts untranslated, and moves texts that disappeared to the end of each `.po` as obsolete (`#~`), so a text that comes back keeps its translation. Comments you write yourself stay where they are (SDK 1.5.13): lines before the header (`# Reviewed by … on 2026-10-25`, `# Translator: …`) and `# ` comments on an entry. A plural entry gets exactly as many `msgstr[n]` lines as the file's `Plural-Forms` has `nplurals`: one for Japanese, Korean and Simplified Chinese (an empty `msgstr[1]` left from an older SDK is removed), two for the others.

`check` reports per language how much is translated, translations that lost or changed a placeholder (keep every `{…}` exactly as in the English; reorder with `{0}`, `{1}` only where the English has them), plural forms missing, a stale `messages.pot`, and text that cannot be translated: a sentence composed in TypeScript, a value that is not a literal, Chinese or other non-English source text, and Slint text without `@tr`. These are warnings, except that `i18n check` fails (exit code 1, SDK 1.5.12) when `messages.pot` is out of date or a `.po` lacks some of its messages: run `extract` and commit the result, so CI catches a forgotten `extract`. `vestra-plugin check` prints the same lines when the plugin has a `locales/` folder; none of them fails `check` or a build.

A note for translators goes in a comment that starts with `TRANSLATORS:` right before the text (in TypeScript on the property or the call, or on an entry of an `as const` table (SDK 1.5.12); in Slint on the line above the `@tr`); `extract` copies it into the files.

```ts nocheck
const REASONS = {
  // TRANSLATORS: the download took longer than 30 seconds.
  timeout: "Connection timed out",
  dns: "Server not found",
} as const;
```

## Machine translations and review

A translation made by a machine (or a language model) is marked as such until a person who knows the language has checked it, so that a reader of the file can tell which entries nobody has looked at yet.

- **Flag each machine-translated entry `x-machine`**, in the entry's `#,` line before its `msgid` (next to `fuzzy`, separated by a comma: `#, fuzzy, x-machine`):

  ```po
  #. The button that adds one to the count.
  #: ui/counter.slint:12
  #, x-machine
  msgid "Add {}"
  msgstr "{} hinzufügen"
  ```

  The flag is only for people. The player and the SDK read `fuzzy` alone (a fuzzy entry is left out of the catalog) and ignore every other flag, so an `x-machine` entry is compiled and shown like any other. `i18n extract` keeps the flag with the translation, also when the text becomes obsolete (`#~`).
- **A review of the whole file goes in a header comment**: a line before the `msgid ""` header, such as `# Reviewed by an AI reviewer on 2026-10-25` or `# Reviewed by Jane Doe on 2026-10-25 (menus and settings)`. `extract` keeps lines before the header (SDK 1.5.13). An automatic review does not replace a human one: it leaves the `x-machine` flags in place.
- **A human reviewer removes the flag.** Someone who knows the language reads each entry, corrects what is wrong and then deletes that entry's `x-machine` (from `#, fuzzy, x-machine` only `x-machine`; remove the `#,` line when nothing is left). An entry still flagged has not been reviewed: `grep -c x-machine locales/de.po` counts what is left. When the whole file is done, the header comment names the reviewer and the date.

Translations written by a person from the start carry no flag.

## Tests

`startPlugin(activate, { directory, locale: "zh-Hans" })` loads `locales/zh-Hans.po` and makes the test host show what a user of that language sees:

```ts nocheck
const { host, plugin, stop } = await startPlugin(activate, { directory, locale: "zh-Hans" });
assert.equal(plugin.i18n.locale, "zh-Hans");
assert.deepEqual(host.command("counter").display.path, ["工具", "计数器…"]);
assert.deepEqual(host.osd, ["计数：1"]); // osd.show("Count: {}", [1])
```

`command.display` is the menu as shown (`display.reason` the shown reason), `host.osd`, `host.osdPanel` and `host.confirmTexts` the shown messages, `host.fileDialogs` the file dialogs' titles and file names, window and panel `props` the property values with their text values shown, `host.translate(text, args)` any text (a string or a text value). The declared English stays in `command.declaration` and `host.sent(...)`. Without `locale`, the plugin's own texts show in English as declared, but the player's own texts (core action OSD messages, menu titles and reasons) stay in Simplified Chinese, as in SDK 1.5.8 and older, so existing tests keep passing; pass `locale: "en"` to see the player in English.

## Limits

- The language changes only at the next start of the player.
- Plurals have two forms (1 and everything else). For a language with more forms (Russian, Arabic, Polish) the player does not ship a translation.
- Numbers in templates print as JavaScript writes them (`1.5`), not in the language's own format.
- A text the player cannot find in the catalog shows in English; so does a plugin's text on a player before 0.4.3, which also shows templates without filling them in. Set `"minPlayerVersion": "0.4.3"` in the manifest of a plugin that relies on templates or text values (older players run an older SDK, which has no `plugin.i18n.text`).
- Text values have limits on arguments, list items, nesting and bytes ([Text values](../reference/limits.md#text-values)); a property value's limits ([Property values](../reference/limits.md#property-values)) count a text value as the string it becomes.
