# Translate a plugin

**Goal:** the plugin shows its menus, windows and messages in the user's interface language (Vestra Player 0.4.3 or later), while its code holds only English source text and no translation code: the player translates.

The languages, file formats, template rules and limits are in [Reference: translations](../reference/i18n.md). Moving an existing plugin written in another language over is in [Migrate a plugin to English source text](../upgrading/i18n-migration.md).

## Steps

### Declare everything in English

What the plugin declares, the player shows translated: command titles and paths, settings page titles, panel titles, command `reason`s, and the manifest's `name`, `punchline`, `description` and `tags`. Menus of different plugins merge by the English words, so write a shared submenu the same way the other plugins do.

```ts nocheck
plugin.commands.add({
  id: "counter",
  path: ["Tools", "Counter…"], // English: menus merge by these words
  run: () => window.show(),
});
```

### Wrap Slint text in `@tr`

A window's texts belong in its `.slint` file. TypeScript passes data (`count`, `step`), never finished sentences.

```slint
title: @tr("Counter");
Text { text: @tr("{n} click" | "{n} clicks" % root.count); }
Button { text: @tr("Add {}", root.step); }
```

### Hand the player templates, not sentences

`osd.show`, `OsdPanel.set` and `dialogs.confirm` take a template and its arguments. Never build the sentence in TypeScript (`` `Speed ${rate}×` ``): a translator can only translate a whole template, and word order differs between languages.

```ts nocheck
await plugin.osd.show("Speed {}×", [rate]);
await plugin.dialogs.confirm({
  message: "Delete {} bookmarks?",
  confirm: "Delete",
  args: [count],
});
```

For what is not text (a date), use the run's language: `date.toLocaleDateString(plugin.i18n.locale)`.

### Text that mixes words and data

For a menu item "Track 2 (opus)", a list whose first item is "No Audio" and the rest track names, or a message whose argument is a sentence of its own, make a **text value** with `plugin.i18n.text(source, args)` (SDK 1.5.11, player 0.4.3) and pass it where a string would go. The player translates `source` and fills in the arguments when it shows it. Write the source as a literal, never `` text(`Track ${n}`) ``.

```ts nocheck
const { text, list } = plugin.i18n;

// A menu item with data (the menu merges by the English "Track 2 (opus)").
plugin.commands.add({
  id: `track-${n}`,
  path: ["@audio", "Audio Track", text("Track {} ({})", [n, codec])],
  run,
});

// A [string] model: fixed words and data in one list.
picker.set({ labels: [text("No Audio"), ...tracks.map((t) => text("Track {} · {}", [t.id, t.title]))] });

// An argument that is a sentence of its own.
await plugin.osd.show("Download failed: {}", [text("Connection timed out")]);

// Items joined the language's way: "a.glsl, b.glsl", "a.glsl、b.glsl".
await plugin.osd.show("Removed missing shaders: {}", [list(missing)]);

// A message of several parts, each translated: "Added: 3, duplicates skipped: 2".
await plugin.osd.show(list([text("Added: {}", [added]), text("duplicates skipped: {}", [skipped])], "clauses"));
```

Where a text value is accepted is in [Reference: translations](../reference/i18n.md#where-a-text-value-is-accepted). For text that leaves the player (the clipboard, a file) only, `plugin.i18n.resolve(value)` returns the translated string: `clipboard.writeText(resolve(list(lines, "lines")))`.

### Leave notes for translators

A comment that starts with `TRANSLATORS:` right before a text is copied into the files:

```ts nocheck
const REASONS = {
  // TRANSLATORS: the download took longer than 30 seconds.
  timeout: "Connection timed out",
  dns: "Server not found",
} as const;
```

### Files

Extract the texts, start a language, translate it in any `.po` editor (Poedit, Lokalize, Weblate, a text editor), and check:

```sh
vestra-plugin i18n extract                # write locales/messages.pot, update every locales/<lang>.po
vestra-plugin i18n extract --locale de    # start a new language: locales/de.po
vestra-plugin i18n check                  # coverage and problems; fails on stale catalogs
```

Commit `locales/` with the code. Run `extract` again after every text change, so `i18n check` (in CI) does not fail on a stale `messages.pot`. `vestra-plugin build` compiles the `.po` files into `dist/locales/`; with `--plugin <dir>` the player reads them directly. The file layout and what each command reports are in [Reference: translations](../reference/i18n.md#files).

### Machine translations and review

When a machine or a language model translated an entry, flag it `x-machine` in the entry's `#,` line, and note a review of the whole file in a comment before the header:

```po
# Reviewed by an AI reviewer on 2026-10-25
msgid ""
msgstr ""
"Language: de\n"

#. The button that adds one to the count.
#: ui/counter.slint:12
#, x-machine
msgid "Add {}"
msgstr "{} hinzufügen"
```

A person who knows the language checks each entry, corrects it and deletes its `x-machine`; `grep -c x-machine locales/de.po` counts what is left. The markers are described in [Reference: translations](../reference/i18n.md#machine-translations-and-review).

### Tests

Start the plugin in another language with `locale` and assert on what a user of that language sees:

```ts nocheck
const { host, plugin, stop } = await startPlugin(activate, { directory, locale: "zh-Hans" });
assert.equal(plugin.i18n.locale, "zh-Hans");
assert.deepEqual(host.command("counter").display.path, ["工具", "计数器…"]);
assert.deepEqual(host.osd, ["计数：1"]); // osd.show("Count: {}", [1])
```

Without `locale` the plugin's texts show in English; pass `locale: "en"` to see the player's own texts in English too.
