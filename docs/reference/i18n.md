# Translations

The rules and formats for translating a plugin. How to do it step by step is in [Translate a plugin](../how-to/i18n.md); the API is {@link "@vestra-player/sdk"!I18n | plugin.i18n}.

A plugin may ship any subset; a `.po` file named after a code not in this table is reported by `i18n check` and never read by the player. The user picks the language in **Settings ▸ Language** (or follows the system); it takes effect at the next start and stays the same for the whole run.

## Where English source text goes

| Place | What | Rule |
| --- | --- | --- |
| Declarations | Command titles and paths, settings page titles (`settings.page`), panel and tab titles (`panels.mount`), command `reason`s, the manifest's `name`, `punchline`, `description` and `tags` | Plain English strings; menus of different plugins merge by the English words. The player's own menus are `Open`, `Playback`, `Subtitles`, `Video`, `Audio`, `Screen`, `Settings` (or `@video` and the other ids). |
| Slint | Every text in a `.slint` file | `@tr("…")` |
| Templates | `osd.show`, `OsdPanel.set`, `dialogs.confirm` | A template and its arguments: `osd.show("Speed {}×", [rate])`; never a sentence built in TypeScript |
| Text values | Text that mixes words and data anywhere a string goes | `plugin.i18n.text(source, args)`, `plugin.i18n.list(items, style)`, `plugin.i18n.error(source, args)` (SDK 1.5.11, player 0.4.3) |

## Templates and `@tr`

- **Placeholders**: `{}` (in order), `{0}`, `{1}` (by position), `{name}` (named, with an object of arguments). A translation keeps every `{…}` of the English exactly; it may reorder with `{0}`, `{1}` only where the English has them.
- **Plurals**: `@tr("{n} click" | "{n} clicks" % root.count)`, where `{n}` is the number. The player has two plural forms: one for `n == 1`, the other for every other number. A `.po` plural entry has as many `msgstr[n]` lines as its `Plural-Forms` `nplurals`: one for Japanese, Korean and Simplified Chinese, two for the others.
- **Context**: `@tr("Menu" => "Open")` tells two meanings of one English word apart.
- **Arguments** are data (strings and numbers, shown as they are) unless they are text values themselves, which are translated too, to any depth (8 levels).
- **Translator notes**: a comment starting with `TRANSLATORS:` right before the text (in TypeScript on the property, the call or an entry of an `as const` table; in Slint on the line above the `@tr`) is copied into the files.

## Where a text value is accepted

| Where | Notes |
| --- | --- |
| `commands.add` `title`, `path` segments, `reason`; `Command.set({ reason })` | not a `list`; the menu merges by the English rendering |
| `osd.show(value)`, `OsdPanel.set(value)`, and as their `args` | a text value as the message carries its own args |
| `dialogs.confirm` `message`, `detail`, `confirm`, `cancel`, `checkbox` | `args` fills only the string ones |
| file dialog `title`; `saveFile` `fileName` | a string `fileName` is data; `text("Playlist.m3u8")` is translated |
| window, panel and settings page properties, where Slint has `string` | at any depth: `[string]` models, struct fields |
| `TimelineLayer.set` mark titles, `subtitles.load({ title })` | a plain string stays data |
| a resolver's failure: `throw plugin.i18n.error("The ROM file was not found.")` | shown translated as the open's failure and `player.state.error` |

`list(items, style)` joins with the interface language's separator: `"list"` (`, ` / `、`), `"clauses"` (`, ` / `，`), `"semicolons"`, `"sentences"` (`. ` / `。`) or `"lines"`. `plugin.i18n.resolve(value)` returns the translated string, for text that leaves the player only (the clipboard, a file). `OsdPanel.set(value, args, { maxColumns })` cuts each line after translation (a Chinese, Japanese or Korean character is two columns).

## Files

```text
locales/
  messages.pot     every text to translate (written by vestra-plugin i18n extract)
  zh-Hans.po       Simplified Chinese
  de.po            German …
```

One `<lang>.po` per language provided, named by its locale code (English is the source and has none). They are ordinary gettext files. `vestra-plugin build` compiles them into `dist/locales/<lang>.json`, which the player reads; during development (`--plugin <dir>`) the player reads the `.po` files directly. An entry flagged `fuzzy` is left out of the catalog.

## What `i18n extract` and `i18n check` do

| Command | Does |
| --- | --- |
| `vestra-plugin i18n extract` | Writes `locales/messages.pot` and updates every `locales/<lang>.po`. Finds every `@tr` in the `.slint` files, the texts given to the calls above and every `text(…)` and `error(…)` source (literals, both branches of a `?:`, `as const` tables, through the TypeScript type checker), and the manifest's display fields. Keeps existing translations, adds new texts untranslated, moves texts that disappeared to the end as obsolete (`#~`), keeps comments before the header and `# ` comments on entries (SDK 1.5.13). |
| `vestra-plugin i18n extract --locale de` | Starts a new language. |
| `vestra-plugin i18n check` | Reports per language how much is translated, translations that lost or changed a placeholder, missing plural forms, a stale `messages.pot`, and text that cannot be translated (a sentence composed in TypeScript, a value that is not a literal, non-English source text, Slint text without `@tr`). Fails (exit code 1, SDK 1.5.12) when `messages.pot` is out of date or a `.po` lacks some of its messages. |

`vestra-plugin check` prints the same lines when the plugin has a `locales/` folder; none of them fails `check` or a build. A source made only of placeholders and punctuation (`"{} ({})"`) is collected like any other, since languages differ in punctuation too.

## Machine translations and review

| Marker | Where | Meaning |
| --- | --- | --- |
| `x-machine` | The entry's `#,` flags line, before its `msgid` (`#, x-machine` or `#, fuzzy, x-machine`) | Made by a machine or a language model; nobody who knows the language has checked it yet. `i18n extract` keeps it, also on obsolete entries. The player and the SDK ignore it: the entry is compiled and shown like any other. |
| `# Reviewed by … on <date>` | A comment line before the `msgid ""` header | A review of the whole file (`# Reviewed by an AI reviewer on 2026-10-25`, `# Reviewed by Jane Doe on 2026-10-25 (menus and settings)`). An automatic review leaves the `x-machine` flags in place. |

A human reviewer deletes an entry's `x-machine` once it is checked (removing the `#,` line when nothing is left); an entry still flagged has not been reviewed. Translations written by a person from the start carry no flag.

## In tests

`startPlugin(activate, { directory, locale: "zh-Hans" })` loads `locales/zh-Hans.po`. Then `command.display` is the menu as shown, `host.osd`, `host.osdPanel` and `host.confirmTexts` the shown messages, `host.fileDialogs` the file dialogs' titles and file names, window and panel `props` the property values with their text values shown, and `host.translate(text, args)` any text. The declared English stays in `command.declaration` and `host.sent(...)`. See [Test host](testing.md#startplugin).

## Limits

- The language changes only at the next start of the player; there is no event and no `t()` function.
- Plurals have two forms (1 and everything else). For a language with more forms (Russian, Arabic, Polish) the player does not ship a translation.
- Numbers in templates print as JavaScript writes them (`1.5`), not in the language's own format.
- A text the player cannot find in the catalog shows in English; so does a plugin's text on a player before 0.4.3, which also shows templates without filling them in. Set `"minPlayerVersion": "0.4.3"` for a plugin that relies on templates or text values.
- Text values have limits on arguments, list items, nesting and bytes ([Text values](limits.md#text-values)); a property value's limits ([Property values](limits.md#property-values)) count a text value as the string it becomes.
